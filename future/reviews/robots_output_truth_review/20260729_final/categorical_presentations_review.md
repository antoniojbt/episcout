# Neutral Review of the EDA Categorical Presentations

## Decision status

This review treats public `summary_version = "v1"` and `summary_version = "v2"` as two presentation contracts, not as an old and improved version of one contract. No categorical behavior, public name or default is changed by this review. The proposed decisions at the end require approval before implementation.

## Why the presentations exist

Spec 008 intentionally retained `v1` as the exact historical two-component EDA output and added `v2` as an opt-in six-component typed output; changing the default was explicitly outside that work (`future/specs/008-univariate-stats-eda-alignment/brief.md:13-18`, `future/specs/008-univariate-stats-eda-alignment/sdd.md:12-19`). The completed implementation likewise records the default transition as a later compatibility decision (`future/specs/008-univariate-stats-eda-alignment/review.md:14-18`, `future/specs/008-univariate-stats-eda-alignment/review.md:25-27`). The current labels therefore encode API history, not a quality ordering.

For this review, `compact` means the current `v1` presentation and `typed` means the current `v2` presentation. These are working descriptions only; accepting them here would not itself add aliases or rename `summary_version`.

## Contract inventory

| Concern | Compact (`v1`) | Typed (`v2`) |
| --- | --- | --- |
| Primary purpose | Preserve the historical report/CSV shape for numeric and categorical summaries | Provide an auditable specification-oriented summary across numeric, categorical, text and temporal types |
| Default | Yes | No |
| Top-level result | Exactly `numeric`, `categorical` | Exactly `variables`, `numeric`, `categorical`, `text`, `temporal`, `skipped` |
| Categorical fields | `name`, `level`, `n`, `p`, `p_observed` | `name`, `level`, `n`, `p_total`, `p_observed`, `is_declared`, `is_unexpected` |
| Missing specified variable | Stops the complete summary call | Records the variable and reason in `variables` and `skipped` |
| Declared zero-count level | Retained | Retained |
| Undeclared observed level when levels are declared | Removed from returned rows | Retained and flagged as unexpected |
| No declared levels | Returns all observed levels | Returns all observed levels |
| Missingness audit | Only implicit through denominators and the source row count | Explicit variable counts plus denominators |
| Empty/all-missing categorical input | Typed empty or declared zero rows, depending on declared/factor levels | Typed empty or declared zero rows, plus variable counts |

These shapes are established by the public adapter and empty-table definitions (`R/eda_summaries.R:12-36`, `R/eda_summaries.R:61-112`, `R/eda_summaries.R:115-202`) and by exact-name tests (`tests/testthat/test-eda-summaries-v2.R:32-50`).

## Independent truth matrix

The following matrix is the proposed hand-authored truth source for categorical behavior. It is intentionally expressed from source observations and the approved denominator rules, not generated by either presentation or the shared core.

Use declared levels `A;B;C`, missing sentinel `UNK`, and source values `A, B, D, NA, UNK, "NA", A`. There are seven source rows. Standard missing and `UNK` are missing, leaving five observed values: `A, B, D, "NA", A`.

| Level | Declared | Unexpected | Count | Proportion of all 7 rows | Proportion of 5 observed rows |
| --- | ---: | ---: | ---: | ---: | ---: |
| `A` | yes | no | 2 | 2/7 | 2/5 |
| `B` | yes | no | 1 | 1/7 | 1/5 |
| `C` | yes | no | 0 | 0 | 0 |
| `D` | no | yes | 1 | 1/7 | 1/5 |
| literal `"NA"` | no | yes | 1 | 1/7 | 1/5 |

The categorical rows sum to five observations, missingness sums to two rows, and together they reconcile to seven source rows. With no declared levels, all four observed labels `A`, `B`, `D` and literal `"NA"` must be present. With all values missing and declared levels present, `A`, `B` and `C` remain as zero-count rows with `p_total = 0` and `p_observed = NA`. With a zero-row source and declared levels present, the same declared rows remain, both proportions are `NA`, and the source-row count is zero. With a zero-row source and no declared levels, the categorical table is a typed zero-row table.

The literal string `"NA"` is an ordinary observed label unless it is explicitly declared as a missing sentinel. This follows the prior edge policy (`future/specs/008-univariate-stats-eda-alignment/sdd.md:31-38`) and is included here because it distinguishes semantic missingness from text equality.

## Findings

### 1. Neither presentation is globally superior

The compact presentation is smaller and maintains exact existing report and CSV schemas; the typed presentation covers more declared types and carries audit fields. Those are different product purposes. The repository provides evidence for both contracts but no product decision that the typed contract should replace the compact one (`future/specs/008-univariate-stats-eda-alignment/sdd.md:10-19`, `future/specs/008-univariate-stats-eda-alignment/sdd.md:44-46`). Treating `v2` as a general improvement would therefore exceed the approved design.

### 2. Both presentations use the same categorical calculation core

Both adapters call `summary_categorical_core()`, which constructs declared and unexpected levels and calculates `p_total` from all source rows and `p_observed` from non-missing observations (`R/eda_summaries.R:67-84`, `R/eda_summaries.R:215-223`, `R/summary_cores.R:112-144`). Agreement between their numeric values is consequently shared-implementation agreement, not independent corroboration.

### 3. The compact presentation can silently conceal real observations

When levels are declared, the compact adapter filters the shared result to `is_declared` rows (`R/eda_summaries.R:68-77`). Unexpected observations remain in both denominators because those proportions were calculated before filtering (`R/summary_cores.R:134-142`). For the truth matrix above, the returned compact categorical counts would sum to three while its observed denominator is five, with no field or warning explaining the two omitted observations. This is not necessarily a wrong proportion, but it is an auditability defect and violates the approved invariant that undeclared non-missing values must not disappear silently.

### 4. The typed categorical presentation exposes this case correctly

The typed adapter returns the full core table, including `is_declared` and `is_unexpected` (`R/eda_summaries.R:215-223`). An existing fixture verifies one unexpected level and a declared zero-count level with literal expected counts and denominators (`tests/testthat/test-eda-summaries-v2.R:43-68`). This makes typed output better suited to categorical conformance auditing, but it does not establish that its larger six-component contract is preferable for all EDA consumers.

### 5. Existing independent evidence is incomplete across the two presentations

The compact fixture independently anchors declared counts and both denominators for standard missingness plus a sentinel, but it contains no unexpected non-missing category (`tests/testthat/test-eda_summaries-fixtures.R:58-88`). The typed fixture anchors declared, zero-count and unexpected levels (`tests/testthat/test-eda-summaries-v2.R:43-68`) and separately checks all-missing categorical behavior (`tests/testthat/test-eda-summaries-v2.R:104-126`). There is no single independent cross-presentation fixture covering unexpected values, literal `"NA"`, absent declarations, all-missing and zero-row cases. The current exact-contract test verifies names and equality between default and explicit `v1`; it does not verify semantic completeness (`tests/testthat/test-eda-summaries-v2.R:32-41`).

### 6. Current documentation implies a migration that was never approved

The public documentation and release notes say compact `v1` remains the default “for one compatibility release” (`R/eda_summaries.R:5-9`, `NEWS.md:11`). That phrase implies an intended default change, whereas the governing spec says the transition remains a later compatibility decision (`future/specs/008-univariate-stats-eda-alignment/review.md:25-27`). Documentation should describe the two purposes neutrally unless and until a migration is separately approved.

## Proposed answers and justification

### Preserve both contracts and the current default

Proposed answer: keep `v1` and `v2`, keep `v1` as the default, and do not deprecate either contract. Justification: consumers may depend on the exact two-table shape, while typed consumers need the richer audit output; the repository contains no evidence that one set of needs has displaced the other. This is the least disruptive choice consistent with the package's specification-first EDA intent.

### Describe purpose rather than progression

Proposed answer: retain `summary_version` and the accepted values `v1`/`v2` for compatibility, but document them as the compact and typed contracts. Add `compact` and `typed` aliases only as an additive usability change if desired; do not rename the argument or remove the historical values. Justification: descriptive language prevents users from assuming `v2` is universally more correct while avoiding a needless breaking rename.

### Make compact unexpected-level loss visible without changing its table schema

Proposed answer: when declared levels exist and unexpected observed values are found, compact output should retain its exact columns and declared-only rows but emit a specific warning containing the variable name, unexpected labels and counts, and recommend the typed presentation when row-level categorical audit details are required. Justification: adding rows or list components would break the exact compact contract; remaining silent is analytically unsafe. A warning makes the existing limitation observable while preserving returned objects. It should be documented and tested from the hand truth matrix.

This is a compromise, not full machine-readable reconciliation within compact output. Consumers that suppress warnings cannot audit the hidden observations from the compact table alone. If machine-readable completeness is required in every returned table, the honest alternatives are to include unexpected rows in compact output or add a diagnostic component, both of which are broader compatibility changes and should be designed separately.

### Leave typed categorical rows unchanged

Proposed answer: preserve the typed categorical representation of declared and unexpected levels, its flags and both denominators. Justification: it already represents the truth matrix without silent loss and matches the design that unexpected observed levels are appended and identified (`future/specs/008-univariate-stats-eda-alignment/sdd.md:31-38`). The repair required here is stronger independent testing, not a categorical calculation redesign.

### Keep the existing denominator definitions

Proposed answer: retain `p_total = level count / all source rows` and `p_observed = level count / all non-missing, non-sentinel observations`, including unexpected observations in the latter denominator. Justification: the definitions are internally coherent, independently hand-calculable and already represented by both public contracts. The defect is concealed numerator categories in compact output, not the denominator mathematics.

## Proposed implementation scope after approval

1. Add the hand-authored truth matrix as discriminating tests for both presentations, including declared zero-count, unexpected, standard missing, sentinel, literal `"NA"`, no-declaration, all-missing and zero-row branches.
2. Add a compact-contract warning for unexpected observed categories while preserving the exact returned list, categorical columns, default and row policy.
3. Update public documentation to call the contracts compact and typed and remove the unapproved “one compatibility release” implication; retain public `v1` and `v2` values.
4. Keep typed categorical calculation and output unchanged unless the new independent tests reveal a separate defect.
5. Record the decision against `TR-009` and `TR-010`; do not regenerate expected files from either adapter or the shared core.

## Approval gate

The recommended decision is to maintain both contracts, keep compact `v1` as the default, clarify their purposes, warn when compact output hides unexpected observed categories, and leave typed `v2` unchanged. No item in this section should be implemented until this separate categorical decision is approved.
