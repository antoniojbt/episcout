# Acceptance

Spec ID: `010-canonical-eda-summary-contract`  
Status: Draft  

- [ ] The brief, SDD and TDD receive human approval before implementation.
- [ ] Focused and full baseline package results are recorded before package-code changes.
- [ ] Expected analytical values are independently calculated and not generated by the production summary path.
- [ ] Statistical conventions and parameters are checked against the official R and installed `e1071` documentation and recorded in `review.md`.
- [ ] `epi_eda_profile_summaries()`, `epi_eda_run()` and `epi_eda_render_report()` expose no `summary_version` argument.
- [ ] No legacy adapter or alternate two-table EDA summary path remains.
- [ ] The canonical result contains the six documented typed components and reconciles every specification variable to a successful or skipped outcome.
- [ ] Missingness, finite-value exclusions, denominators, categorical declarations, text states and temporal parsing follow the SDD policies.
- [ ] All-missing and infinite-only numeric inputs do not report a zero sum as if observed values totalled zero.
- [ ] Missing variables have unavailable observation counts and explicit required/optional context.
- [ ] Dictionary-derived specifications produce the same canonical contract as directly supplied specifications.
- [ ] Workflow CSV and rendered report values come from the returned canonical summary without alternate calculations.
- [ ] The report makes variable coverage, skipped reasons, finite-value exclusions, categorical denominators, temporal units and empty components explicit.
- [ ] Typed `epi_stats_summary()` uses the canonical builder; current-mode schemas and unrelated values remain regression-tested; and the authorised no-observed-total correction is documented for numeric output.
- [ ] Roxygen documentation, README, NEWS, vignette and report template describe only the canonical contract; generated documentation is refreshed.
- [ ] Relevant changed R files are styled, package-loaded lint is clean and focused tests pass.
- [ ] `scripts/check-local.sh` and `scripts/check-cran.sh` pass, or every failure is reported and resolved before implementation is accepted.
- [ ] Returned tables, written CSV files, rendered HTML and the source package contents are inspected directly.
- [ ] Review findings and verification evidence are recorded in `review.md`.
- [ ] No tag or release is created as part of this specification.
