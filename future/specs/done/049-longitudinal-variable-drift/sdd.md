# Software Design

Spec ID: `049`
Status: Completed

## Frozen implementation decisions after #346 closeout (2026-08-17)

1. **Public API.** The exact additive API is `epi_eda_longitudinal_drift(sources, spec, variables = NULL, max_levels = 50L)`. `sources` is a named ordered list of at least two unmodified `epi_eda_postgres_source` objects on the same open connection. All five persistent relation kinds accepted by #346 remain accepted. `spec` is the validated data frame returned by `epi_eda_spec()`. `variables = NULL` selects every specification row in specification order; otherwise it is a unique non-blank character vector, every name must occur in `spec`, and caller order is authoritative.

2. **Supported summaries.** `numeric` and `integer` receive numeric drift; `categorical` and `binary` receive categorical drift; `date` and `datetime` receive temporal drift. Every selected type receives schema and missingness evidence. `text` receives schema and missingness evidence and an explicit `unsupported_analysis_type` row for distribution drift; it is not silently omitted.

3. **Exact result envelope.** The class is `c("epi_eda_longitudinal_drift", "list")`. Components, in order, are `metadata`, `schema`, `missingness`, `missingness_adjacent`, `numeric`, `numeric_adjacent`, `categorical`, `categorical_adjacent`, `temporal`, `temporal_adjacent`, `skipped`. Empty components retain their typed columns.

4. **Period/variable keys and ordering.** Every table begins with `period_index`, `period`, `variable_index`, `variable`, except adjacent tables, which begin with `left_period_index`, `left_period`, `right_period_index`, `right_period`, `variable_index`, `variable`. Indices are integer; labels/names are character. Period order follows `sources`, variable order follows the resolved selection, declared categorical levels retain specification order, and unexpected levels use bytewise C ordering. Adjacent output contains only consecutive source pairs.

5. **Schema table.** Exact remaining columns are `analysis_type`, `expected_database_type`, `observed_type`, `observed_present`, `type_status`, `type_reason`. Presence and compatibility values reuse `eda_postgres_schema_inside()`/`epi_eda_check_schema()` semantics; no second compatibility vocabulary is introduced. Undeclared source columns are outside this selected-variable comparison and are not emitted.

6. **Missingness tables.** `missingness` adds `n`, `n_missing`, `n_observed`, `p_missing`, `status`, `reason`. `missingness_adjacent` adds `n_left`, `n_missing_left`, `n_observed_left`, `p_missing_left`, `n_right`, `n_missing_right`, `n_observed_right`, `p_missing_right`, `absolute_change`, `relative_change`, `relative_denominator`, `status`, `reason`. `absolute_change = p_missing_right - p_missing_left`. `relative_change = absolute_change / p_missing_left`, `relative_denominator = p_missing_left`, and both are `NA_real_` when the left proportion is zero or either period is unavailable. Proportions are fractions, not percentage-point integers.

7. **Numeric tables.** Period output adds exactly `n`, `n_missing`, `n_observed`, `n_infinite`, `n_finite`, `min`, `q1`, `mean`, `median`, `q3`, `max`, `iqr`, `sd`, `status`, `reason`, using the canonical PostgreSQL summary definitions including type-7 quantiles and finite-value rules. Adjacent output contains left/right values and `change = right - left` for `min`, `q1`, `mean`, `median`, `q3`, `max`, `iqr`, and `sd`, plus left/right `n_finite`, `status`, and `reason`; it adds no tests, scores, percentages, or inferred interpretation.

8. **Categorical tables and hard bound.** Period output adds `level`, `n`, `p_total`, `p_observed`, `is_declared`, `is_unexpected`, `status`, `reason`, reusing canonical categorical denominators. Missing values are represented only in `missingness`, never as a synthetic level. Adjacent output uses the ordered union of levels and adds left/right counts and both canonical proportions, both proportion differences, and `level_status` in `introduced`, `removed`, `present_both`, `absent_both`. Introduction/removal is determined by positive observed counts, not declaration alone. `max_levels` is a positive whole-number hard limit applied to declared levels, each observed period domain, and each adjacent union. Preflight queries fetch at most `max_levels + 1` distinct levels. Any excess is a hard error and no result object is returned; default `50L` matches the existing catalogue-profile protection. This issue must add the missing bound rather than call the current unbounded categorical query with `limit = Inf`.

9. **Temporal tables.** Period output adds canonical `n`, `n_missing`, `n_observed`, `min`, `max`, `range_value`, `unit`, `status`, `reason`; date output uses days and datetime output uses seconds/UTC canonical formatting. Adjacent output adds left/right minimum, maximum and range, numeric `min_shift`, `max_shift`, `range_change` in the canonical unit, `unit`, `status`, and `reason`. No expected cadence or coverage is inferred.

10. **Nonfatal audit versus hard failure.** A selected variable absent from a period, storage/type incompatible with its declaration, invalid for the declared missing-code contract, or `text` for distribution summaries yields explicit schema/missingness or `skipped` evidence with unavailable metrics as typed `NA`; other variables still complete. `skipped` columns are `period_index`, `period`, `variable_index`, `variable`, `component`, `code`, `message`; stable codes are `absent_variable`, `incompatible_type`, `invalid_missing_contract`, `unsupported_analysis_type`, `zero_denominator`. Invalid inputs, changed/unapproved sources, mixed connections, transaction/SQL/catalogue failures, count overflow, categorical-bound excess, or reconciliation failure are hard errors and return no partial object.

11. **Count and snapshot compatibility.** To reuse the canonical single-period summaries literally, public count columns retain their existing R integer contract and fail through `eda_checked_count()` above `.Machine$integer.max`; #347 does not silently introduce a second count type into those summaries. A broader canonical count-range migration requires its own compatibility change. All source validation, bounded preflights, period summaries, and adjacent assembly occur within one `REPEATABLE READ READ ONLY` transaction. Extract a neutrally named internal multi-source transaction helper from #346 rather than copying a QC-named wrapper. The connection remains open and reusable after success or rollback; no database object is written.

12. **Metadata and evidence.** `metadata` records contract version, ordered period labels/fingerprints, specification fingerprint, resolved variables, `max_levels`, count contract, and snapshot mode without source values. Tests must compare every period summary with the canonical single-period PostgreSQL EDA result, use hand-derived adjacent truth, prove the 51st level fails without an object, prove a second-connection write is invisible within the snapshot, prove rollback/reuse after forced failure, and scan normal results/errors for fixture identifiers.

## Internal Design

Extract the #346 transaction wrapper into a neutral multi-source helper. Within it, reuse `eda_postgres_schema_inside()`, `eda_postgres_missing_inside()`, `eda_postgres_summaries_inside()` and the canonical PostgreSQL summary helpers. Add only bounded categorical preflight and aggregate assembly. No source rows or values are collected.
