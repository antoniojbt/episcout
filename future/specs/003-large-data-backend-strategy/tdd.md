# Test Design

Spec ID: `003-large-data-backend-strategy`
Status: Active

## Test Authority

Tests establish the SDD contracts; they do not treat agreement between two production paths as independent proof. The canonical definitions in the reviewed SDD and `summary_cores.R`, R's documented type-7 quantile rule, hand calculations and PostgreSQL's documented transaction/aggregate semantics are the bases for expectations. Existing tests establish compatibility evidence only.

Expected-output fixtures must not be generated by `epi_eda_*`, database query helpers, shared canonical builders or copied production formulas. A fixture provenance note identifies the human calculation, independent tool or authoritative definition for each expected field. Source guards fail if a fixture generator loads episcout, sources `R/`, calls production helpers or reads production outputs.

## Baseline Gate

Before package-code changes, record current branch/commit, package-loaded lint, full tests, `scripts/check-local.sh` and `scripts/check-cran.sh` results in `review.md`. Preserve inherited failures verbatim and do not weaken their tests. Planning-file edits under `.Rbuildignore` do not invalidate this baseline; package changes do.

## Neutral Fixture Matrix

| Fixture feature | Independent expectation |
| --- | --- |
| zero-row relation and all-missing variables | zero/`NA` schemas and count identities written by hand |
| numeric finite values with non-integer quartiles | type-7 order-statistic calculation written independently, with hand fences/outlier counts |
| positive/negative infinity and PostgreSQL NaN | explicit missing/observed/finite partitions and signed non-finite assertions |
| constant, singleton, 2/3/4/4,999/5,000 finite values | exact variance/shape/Shapiro eligibility boundaries; only bounded test vectors use constructed sequences |
| integer boundaries | supported int2/int4/int8 values, exact-double limit and canonical count overflow refusal |
| declared, empty, unexpected and sentinel categorical levels | literal frequency counts with both denominators and stable ordering |
| boolean binary and two-level encoded binary | reviewed level mapping, unexpected/missing behaviour |
| text | empty, ASCII whitespace, combining/Unicode characters and sentinel values with hand character counts; no committed raw expected-value artifact beyond the neutral fixture itself |
| date and timestamptz | epoch-day/second type-7 values and UTC formatting derived independently |
| unsupported timestamp without time zone | explicit incompatibility and reviewed-view recommendation |
| non-syntactic, Unicode and SQL-looking identifiers | exact DBI-quoted resolution without execution or name alteration |
| identifier duplicates | hand `n_distinct`, repeated-value, duplicate-excess and maximum-frequency counts; no expected value list |
| absent required/optional and extra source columns | current canonical presence/type/status/reason rows |
| high-cardinality categorical display | complete canonical frequencies plus independently summed leading/remainder plot counts |

The main parity fixture is deliberately small enough to inspect row by row. Large Shapiro boundary and performance fixtures test resource gates but do not become the authority for ordinary summary values.

## Source And Dispatch Tests

- [ ] Constructor rejects closed/non-PostgreSQL connections, active transactions, empty/dotted/SQL names, temporary/unsupported objects, missing relations and ambiguous relation identities.
- [ ] Constructor accepts each authorised relation kind and records only value-free catalogue metadata; print/structure omit the connection and all host/database/user/credential attributes.
- [ ] Replacing, dropping or changing a relation/column after construction fails revalidation before analytical query results or output publication.
- [ ] Existing profilers accept only data frames or the explicit PostgreSQL source class; arbitrary DBI connections, `tbl_dbi` and forged lists do not trigger database dispatch.
- [ ] Ordinary data-frame calls preserve arguments, component names, column classes/order, plot-list membership and input identity.
- [ ] `RPostgres` absence affects PostgreSQL calls only and gives an actionable optional-dependency error.

## Schema And Type Tests

- [ ] Every supported PostgreSQL type maps to the declared episcout type/status/reason contract; every excluded type has an explicit value-free incompatibility reason.
- [ ] Numeric NaN, infinities, bigint exactness, unsupported numeric magnitude and count overflow follow the SDD without coercion or zero substitution.
- [ ] Deterministic and nondeterministic text collation cases are distinguished; unsafe equality semantics block categorical/text aggregation.
- [ ] Native date and timestamptz pass; timestamp without time zone and implicit character temporal parsing do not use the session timezone.
- [ ] Schema output exactly matches the current eight-column contract and keeps specification rows before catalogue-order unexpected columns.
- [ ] Missing required/optional variables and extra columns retain independently checked presence and reason semantics.

## Missingness And Sentinel Tests

- [ ] Literal `NULL`, numeric NaN, positive/negative infinity, ordinary values and every supported typed sentinel reconcile independently for all seven specification types.
- [ ] Invalid, out-of-range and timezone-ambiguous sentinels produce variable incompatibility rather than an ignored code or SQL error containing the value.
- [ ] Bound text values containing quotes, semicolons, wildcard characters, comment markers and Unicode are compared literally and cannot alter SQL.
- [ ] Empty and zero-row denominators remain `NA`, not zero; `n_missing + n_observed = n` for every present variable.
- [ ] Missing identifier counts are aggregate-only and contain no observed identifier value.

## Canonical Summary Tests

- [ ] All six component names, zero-row schemas, column classes/order, specification order and skip rows exactly match the data-frame contract.
- [ ] Numeric discrete counts, empty cases, infinities, sums, type-7 quantiles, moments, shape statistics, Shapiro eligibility, fences and outliers agree with independent expectations; floating fields use the predeclared tolerance and non-finite values compare by class/sign.
- [ ] PostgreSQL `percentile_cont` is tested against explicit type-7 calculations for `n = 1` through at least `n = 12`, ties, negatives and non-integer probabilities used by the package. If any case differs, implementation uses an explicit type-7 query instead.
- [ ] Skewness and kurtosis are checked against a hand/independent e1071 type-3 benchmark that does not call the production builder; numerically difficult centred values exercise cancellation tolerance.
- [ ] Query instrumentation proves only a Shapiro-eligible finite vector is fetched and never more than 4,999 values; `n = 5,000`, constants and ineligible sizes fetch no vector.
- [ ] Complete categorical results include declared zeros and unexpected levels with exact counts, `p_total` and `p_observed`; client ordering is independent of database collation order.
- [ ] Text returns only counts and length extrema; PostgreSQL character counts agree with R character semantics for the neutral Unicode fixture.
- [ ] Date/datetime fields, quantiles, UTC strings, sub-second policy and range units match independent epoch calculations.
- [ ] Every present non-identifier component reconciles to the relation-wide count and every specification variable is summarised or explicitly skipped.
- [ ] Identifier roles never enter numeric/categorical/text/temporal rows; their separate QA counts satisfy `duplicate_excess = n_observed - n_distinct` and contain no values.

## Snapshot, Read-only And Lifecycle Tests

- [ ] A second connection changes committed source rows between stage queries while one run holds its snapshot; all run counts remain internally consistent with the initial repeatable-read snapshot.
- [ ] Direct profiler calls each use one stable read-only snapshot and reject rather than disturb a caller-owned transaction.
- [ ] A database role with `SELECT` only can complete the workflow; statement auditing in the test database observes no `INSERT`, `UPDATE`, `DELETE`, DDL, temporary object, lock-management or session-wide configuration change from episcout.
- [ ] Success, query error, cancellation/timeout simulation, renderer error and filesystem error all clear results/end the owned transaction and leave the caller connection open and usable.
- [ ] Source row contents, row counts, columns, constraints, indexes, privileges and relation identity remain unchanged after successful and failed calls.

## SQL And Privacy Tests

- [ ] All identifiers pass through DBI quoting and all specification values use binding; mock/spy tests fail on raw concatenation of caller values.
- [ ] Stable friendly conditions do not forward native messages that can include observations, SQL, parameters or connection details.
- [ ] A runtime-generated set of opaque canaries placed in identifiers, free text, sentinels, connection metadata and database errors is absent from default return objects, print/structure output, conditions, timings, SVGs, CSVs and manifests except caller-authored sentinels intentionally retained in the normalized specification artifact.
- [ ] The specification exception is documented and classified `specification_review`; canaries prove it is not copied into other artifacts or diagnostics.
- [ ] Query-result instrumentation enforces scalar/30-row/4,999-row/catalogue limits and records the complete categorical-frequency exception explicitly; an unexpected oversized fetch aborts.
- [ ] No plot data or SVG contains raw text or identifier values, including labels, tooltips, XML metadata and filenames.
- [ ] Repository content scanning over touched fixtures/docs finds no credential, connection string, developer path or representative workload/project terminology.

## Plot Tests

- [ ] Data-frame and PostgreSQL compact plot-data tables match exactly for the neutral fixture before rendering.
- [ ] Histogram boundary, constant, zero-row, missing, infinity and 30-bin totals reconcile independently with canonical counts.
- [ ] Quantile-box fields match canonical numeric summaries and show aggregate below/above counts without raw points.
- [ ] Categorical leading-level selection, tie order, declared zeros and explicit remainder counts reconcile to complete frequencies for `max_plot_levels` boundaries.
- [ ] Text plots use lengths and never raw strings; temporal plots use the canonical epoch/timezone/missing exclusions.
- [ ] Identifier entries are named `NULL` in direct plot output and `not_created` with a reason in the inventory.
- [ ] Representative SVGs have deterministic names, dimensions, labels, scales and non-empty valid XML; underlying compact data are asserted before visual snapshots.
- [ ] Exact delivered SVGs are rendered and visually inspected for clipping, empty/constant cases, Unicode labels, high-cardinality remainder, contrast and readability.

## Bundle And Failure Tests

- [ ] Return components and every CSV use the fixed SDD schemas and order; `plots = FALSE` writes no SVG and records explicit not-created inventory rows.
- [ ] Manifest created rows correspond exactly to regular bundle files, paths are relative, checksums match and sensitivity classifications are exact.
- [ ] Dynamic plot manifest rows are deterministic and never use variable names in paths.
- [ ] New/empty targets work; non-empty targets require `overwrite = TRUE` plus an exact valid prior database-EDA manifest, registered entries and checksums.
- [ ] Intake manifests, unowned/missing/modified files, changed spec registry, symlinks, directories and special entries are refused before staging/target mutation.
- [ ] Injected failure at every publication boundary leaves the prior target byte-identical or restores it; owned staging/backup cleanup is verified without broad deletion.
- [ ] Source/spec/options fingerprints and metadata are truthful, while connection host/database/user/password and absolute source/spec paths are absent.
- [ ] Re-running an unchanged fixture yields identical analytical rows, statuses, inventory and filenames apart from documented timestamps/timings/checksums.

## Performance And Data-locality Evidence

- [ ] A small instrumented test records rows returned per query kind and proves M-002.
- [ ] A synthetic scale test demonstrates client memory grows with aggregate cardinality/plot bins, not relation row count, while acknowledging complete categorical frequencies.
- [ ] The external evidence custodian records the benchmark protocol fields, warm-up and three end-to-end runs without repository-specific names or values.
- [ ] The median external runtime is at most 300 seconds and every run completes with reconciled counts, privacy checks and bounded-fetch evidence.
- [ ] The separate data-frame limitation record states the policy or measured memory/materialisation reason without exporting restricted rows.
- [ ] A missed threshold produces profiling evidence and an owner decision; it does not silently activate approximation, sampling, extra connections or changed statistics.

## Documentation And Compatibility Tests

- [ ] Roxygen and README show construction, direct profiling and run/bundle use with neutral disposable PostgreSQL examples and prominent aggregate-disclosure limitations.
- [ ] The specification-first vignette explains reviewed view casts, idle connection/read-only snapshot behaviour, identifier QA, unsupported timestamp-without-time-zone and bundle review.
- [ ] Data-frame quickstarts remain executable and identify the text-length/identifier plot policy change.
- [ ] Installed help/vignette discovery works from a clean source package; rendered documentation is inspected.
- [ ] The full prior data-frame, intake, dictionary, PostgreSQL security and plot suites pass without weakened expectations.

## Verification Order And Commands

Run focused tests before broad checks. Use the repository wrapper and the existing PostgreSQL integration environment; never use a real restricted schema for tests.

```bash
scripts/rscript_env_caller.R -e "options(repos = c(CRAN = 'https://cloud.r-project.org')); devtools::test(filter = 'eda-postgres|eda-summaries|eda-missing|eda-schema|eda-plots|eda-intake|db-dictionary', reporter = 'summary')"
scripts/rscript_env_caller.R -e "devtools::load_all(quiet = TRUE); findings <- lintr::lint_package(); print(findings); if (length(findings) > 0L) quit(status = 1L)"
EPISCOUT_TEST_POSTGRES=1 scripts/rscript_env_caller.R -e "options(repos = c(CRAN = 'https://cloud.r-project.org')); devtools::test(filter = 'eda-postgres|security-postgres', reporter = 'summary')"
scripts/check-local.sh
scripts/check-cran.sh
git diff --check
```

Implementation review reports exact commands/outcomes, PostgreSQL version, expectation counts, rendered files inspected, independent expected-value provenance, external benchmark summary, data-locality evidence, inherited/external failures and checks not run. Passing execution alone is not statistical or privacy validation.
