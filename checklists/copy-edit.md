# Copy-Edit Checklist

Apply this checklist to README, NEWS, vignettes, roxygen documentation, captions and other user-facing prose. Complete substantive review before treating a task as copy-editing.

## Blocking checks

- [ ] Confirm that the revised deliverable still fulfils the requested communication end goal; do not let brevity, package style, structural consistency or the existing draft silently narrow or substitute it.
- [ ] Preserve verified facts, values, directions of effect, uncertainty, technical meaning, citations and conclusions; revalidate any edit that changes them.
- [ ] Check names, dates, units, numerical values, table and figure references, citations, links and cross-references against their sources.
- [ ] Keep claims within the strength and scope of supporting evidence and retain material limitations when shortening.
- [ ] Resolve or explicitly retain placeholders, comments and editorial queries.
- [ ] Preserve confidentiality controls and remove tracking parameters from reported links.

## Quality checks

- [ ] Match the intended audience, register, terminology and British English spelling.
- [ ] Improve clarity, flow, grammar, punctuation, headings, lists and captions without introducing unsupported content.
- [ ] Remove ambiguity, repetition, filler, decorative wording, unsupported emphasis and unexplained abbreviations.
- [ ] Check numbering, references, terminology, formatting and capitalisation consistently across the complete deliverable.
- [ ] Read revised text in context and apply `render-and-release.md` when the output is rendered.

## Evidence to report

Report the files or sections reviewed, source checks performed, substantive changes requiring revalidation, unresolved queries and whether rendered output was inspected.
